# agent-harness 2.0.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade the `agent-harness` Claude Code plugin to v2.0.0. Setup becomes scan-first and runs layer by layer. It gains a read-only audit with a measured maturity level, proven project-specific sensors, a one-command dev setup that works on a fresh machine or in any worktree, and a multi-repo workspace mode that only warns and never writes into member repos.

**Architecture:** Deterministic work goes into bash/python scripts that are unit-tested against fixture repos:
- `scan.py` scans the repo;
- `level.py` measures the level;
- `harness-cmd.sh` resolves commands;
- `sensor-proof.sh` proves sensors;
- `setup.sh` runs dev setup;
- the guards guard.

Judgement work goes into skills and agents (markdown) that call those scripts. Plugin-side scripts live in `plugins/agent-harness/scripts/`. Files copied into target repos live in `skills/*/assets/`.

**Tech Stack:** bash 3.2+ (macOS default), python3 (stdlib only), GNU/BSD make, git. No new dependencies.

**Spec:** `docs/specs/2026-10-26-harness-v2-design.md`

## Global Constraints

- Never name a third-party plugin or skill pack anywhere in plugin text (skills, agents, templates, scripts, README).
- Hooks **fail open**: a missing python3, make or file → allow and stay quiet. They block only on an explicit rule.
- Scripts are quiet on success (one line) and loud on failure (the problem, the file, the fix).
- Python is stdlib-only and runs as `python3`. Bash must work on macOS bash 3.2: no `declare -A`, no `${var,,}`, no `mapfile`.
- Default budgets: root `AGENTS.md` ≤ 100 lines (warn), > 120 (fail); auto-loaded set > 3000 tokens (warn), > 5000 (fail); module `AGENTS.md` ≤ 80; `SKILL.md` ≤ 120 lines. Overridable via `## Context Budget` / `## File Size Budget` in `INVARIANTS.md`.
- Invariant line format: `- <rule> — Severity: <Critical|Important|Nice-to-have> — Enforced by: <…>`.
- Level names, exactly: `Experimental`, `Functional`, `Robust`, `Enterprise`. Layer keys, exactly: `guides`, `sensors`, `context`, `tools`, `observability`.
- Persisted audit data is script-measured only. Agent judgements stay in the conversation.
- Nothing the plugin runs uses `sudo`, fetches secrets or writes `.env`. `seed` and `reset` refuse non-local targets.
- Commit messages: if a Jira key exists for this work, put it first on line 1. **No `Co-Authored-By` trailer.**
- Version `2.0.0` in `plugin.json` and `marketplace.json`.

## Review Focus

1. **A repo with an existing `Makefile` that already defines `help`, `setup` or `check`**: including `harness.mk` must not redefine those targets or break `make`. Test: `test_harness_mk.sh::existing_targets_not_clobbered` (Task 4).
2. **Paths with spaces and worktrees** (a `.git` file, not a directory): scan, the stop gate, `harness-cmd` and `setup.sh` must treat a worktree as a repo. Tests: `test_scan.sh::worktree_is_repo`, `test_setup.sh::worktree_project_name` (Tasks 5, 12).
3. **A half-built harness** (skeleton with TODOs, gate not wired): the stop gate must not block, and lint must only warn. Tests: `test_stop_gate.sh::silent_when_unwired`, `test_lint.sh::todo_is_warning` (Tasks 6, 7).
4. **Malformed `.agents/harness.json`**: it must fall back to `make` with a warning on stderr, not crash the hooks. Test: `test_harness_cmd.sh::bad_json_falls_back` (Task 3).
5. **A workspace member repo that has no git remote or isn't checked out**: `ws.sh status`/`check`/`setup` must warn and continue. Test: `test_workspace.sh::missing_member_warns` (Task 11).

### Task 8: Level and layer measurement (`level.py`) + audit log

**Files:**
- Create: `plugins/agent-harness/scripts/level.py`
- Test: `tests/test_level.sh`

**Interfaces:**
- Produces `level.py <repo-dir> [--json] [--log]`:
  ```json
  { "level": "Functional", "target": "Robust",
    "layers": {"guides": {"score": 0.8, "missing": ["…"]}, "sensors": {...}, "context": {...}, "tools": {...}, "observability": {...}},
    "next_level_blockers": ["no permission rules in .claude/settings.json", "2 security/data invariants not yet enforced"],
    "tokens": 2140 }
  ```
  - `--log` appends one line to `docs/harness/AUDIT-LOG.md`, creating the header if missing:
    `| YYYY-MM-DD | <level> | g=0.80 s=… c=… t=… o=… | health=<n or -> | tokens=<n> |`
  - `--health <n>` lets the skill pass the full-audit health score through, so it gets logged.
- Criteria (spec §7.2), each a function `crit_<name>(repo) -> (bool, reason)`:
  - **Experimental**: `AGENTS.md` and `INVARIANTS.md` exist, `CLAUDE.md` is a shim or absent, lint exits 0.
  - **Functional**:
    - `harness-cmd check` resolves and exits 0;
    - automatic enforcement: `.githooks/pre-commit` exists and `git config core.hooksPath` is `.githooks`, **or** the hook manager config mentions `check-fast`, **or** a CI file mentions `check`;
    - at least one invariant has `Enforced by:` naming a make target, sensor, hook or CI job.
  - **Robust**:
    - `docs/plans/` exists;
    - `.claude/settings.json` has `permissions.deny`;
    - `registry.json` has at least 1 sensor and its recheck passes;
    - lint has no budget fail;
    - `AGENTS.md` contains `Cadence`;
    - every invariant under `## Security` / `## Data Integrity` has `Enforced by:` that isn't `not yet enforced`.
  - **Enterprise**:
    - a CI file runs `check`;
    - `.claude/settings.json` `enabledPlugins` pins the harness;
    - CODEOWNERS covers `AGENTS.md` and `INVARIANTS.md`;
    - `AUDIT-LOG.md` has at least 2 rows and the last level is ≥ the previous one;
    - if it's a workspace, every member is Functional or higher.
- The target comes from the `Harness target: <Level>` line in `INVARIANTS.md` (default `Robust`).
- Layer score = criteria for that layer met ÷ total. Each criterion maps to a layer.
- `check` is executed only when `--run-checks` is passed. Without it, `check` passing is read from `.harness/last-check` (written by the stop gate and `harness-verify`) to avoid slow audits.

  - `t_experimental`.
  - `t_functional_via_githooks`.

  - `t_robust_blocked_by_unenforced_security`: blockers list contains `not yet enforced`.
  - `t_target_read`.
